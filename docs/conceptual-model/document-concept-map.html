Making documents with Souvenir: concept map, draft v0.0

Every concept a person meets when they ask Souvenir for a document, and how the concepts relate. Drawn from the Round 1 leanings; the six forced choices are still open, so the terms marked ? can change.

Entity something a person can see and talk about relationship link label can be: Operation what a person can do to it Gray to be added later ? waits on a Round 1 choice

Open choices shaping this map

  1. Document? as the root concept, rather than a standalone file per request.
  2. Only exportable, versioned results are documents; a long reply is just a reply.
  3. Refining makes a new version of the same document.
  4. A file is the result of exporting a version, not a thing of its own.
  5. Missing is a status a fact has, shown where the fact belongs.
  6. Look? is drawn gray: whether people see and change it is undecided.

Names kept out of the model

  • Artifact, output, generated file: other names for the document. Use “document”.
  • Revision, draft (as a noun): other names for a version. “Draft” survives only as a readiness value.
  • Skill, tool, sandbox command, snapshot, block: system concepts. They stay hidden.

System behaviour, not operations

  • Drafting: Souvenir is making a version. People watch it; they don't do it.
  • Readiness is worked out from the facts; nobody sets it by hand.
